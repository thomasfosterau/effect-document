# @thomasfosterau/effect-document (packages/core)

The document schema (`src/schema`: the AST as `Schema.TaggedClass` nodes, attributes, the feature taxonomy, constructors), the profile system (`src/profile`: `defineProfile`, `Doc<F>`, conformance, `widen` / `narrow`, the built-in profiles) and the I/O pipeline (`src/io`: `Content`, `Reader` / `Writer` / `Format`, the tagged errors, `convert`). Every other package depends on it.

## Boundary

Peer: `effect`. Imports nothing from this workspace and no format: `.fallowrc.json` zone `core`, no outbound rule. A format-specific rule (an OOXML style, a PDF font) never lives here; it goes in the format's package, behind its own profile.

## Invariants

- **The schema is the wire format.** Every node encodes to plain JSON and decodes back (`Schema.encode` / `decode` of `Document`); a node added without its `*Encoded` interface and a place in the `Inline` / `Block` / `SheetCell` / `Shape` unions breaks that round trip. The stack-safe codec (`encodeDocument` / `decodeDocument` in `schema/codec.ts`, #191) must agree with it: a new node also gets an entry in that file's kind tables, naming its recursive fields, or deep documents of it overflow again (`test/schema/codec.test.ts` has a chain per recursive field).
- **Every node tag maps to exactly one feature** (`TAG_FEATURE` in `feature.ts`), and attribute facets are features too (`attr.id`, `attr.classes`, `attr.style`, `attr.keyValue`). A new node adds its tag there, to the right `ALL_*_FEATURES` group, to `narrow`'s handling and to `collectFeatures`.
- **`Doc<F>` is a phantom brand; only `defineProfile`'s `validate` / `schema`, `narrow` and `trustAs` produce one.** `trustAs` is the unchecked escape hatch for code that built the document itself; readers use it for their own output, never for input they did not produce.
- **`narrow` never drops silently.** Every node or facet it removes or down-converts is a `LossEntry` (`dropped` or `converted`, with a detail), in document order; `convert` returns the same report. A lossless narrowing reports `isLossless`.
- **The constructors skip the schema pass only for input they have checked** (`schema/trusted.ts`): `cell.text` / `number` / `boolean` / `blank`, `str`, `sheetRow`, `sheetRowFrom`, `sheetRowOf`, `sheetRowOfNumbers` (a row of plain numbers, checked by a loop that meets only arrays of doubles, so V8 never boxes them; `every` boxes each), `sparseRow`, `worksheet` and `worksheetFromRows` (its `numberRows` hint sends the listed plain rows to the same loop) build the node on its class's prototype when their guards show the struct would accept the input unchanged, and otherwise call the class constructor, so invalid input fails exactly as `new` does. A trusted node is `instanceof` its class, `Equal.equals` to the `new` one, and has the same own keys in the same order (`sparseRow` omits `height` as `new SheetRow` without one does); a new fast path keeps all three, and its test compares it against `new`.
- **A row's cells are positional** (#226, owner decision: Option A, then plain cells): the cell at array position `n` is in column `n` (a node, or a `PlainCell`: a finite number, string or boolean standing for its unstyled node, written as the bare JSON value), `undefined` is a gap (`null` in JSON, which `RowCell` and the stack-safe codec's `positions` field translate), and the last position holds a cell, so a row has one form and its width is `cells.length`. Rows stay sparse (a worksheet holds only the rows it has), but a far-right cell costs its row's width: a reader that takes untrusted input bounds positions, not cells (the XLSX reader's `maxCells`). Never build a row with array holes; `positional` fills gaps with `undefined`. Code that reads cells goes through `cellOf` / `cellAt` / `rowEntries`, which give the node for a plain cell; a plain cell and its node are the same cell but not `Equal`.
- **A worksheet row is a `SheetRow` or a plain row** (#227, owner decision): a `PlainRow` is a row's positional cells alone, standing for the `SheetRow` one past the row before it (row 0 when first) with no height, written as a bare JSON array (the stack-safe codec's `sheetRows` field). The order check runs on implied indexes, so a `SheetRow` must come after the plain rows before it. Readers emit plain rows for consecutive rows without a height (CSV always; XLSX whenever a row follows on), so a document costs no node per row. Code that reads rows goes through `rowsOf` (nodes), `rowIndexes` and `rowCellsOf` (no nodes); `rowEntries` and `cellAt` take either form. A plain row and its node are the same row but not `Equal`.
- **Errors are tagged and carried in the error channel**: `ParseError` (format, reason, optional source position, cause), `WriteError`, `ProfileViolation` (the unsupported features), `ConversionError` (a format missing its reader or writer). Their tags and field names are API: every format package constructs them.

## Terms

- **Feature** — one capability a document can use: a node kind (`block.header`, `cell.date`) or an attribute facet (`attr.style`). An id is collected as its node's id facet (`attr.id.header`, #184); a profile listing `attr.id` gets every id facet, one listing a few allows ids on those nodes only. A new node with an `attr` field gets an entry in `ID_FEATURE` and passes its tag to `narrowAttr`.
- **Profile** — a named feature set with its attribute policy, the type `Doc<F>` it brands, a runtime check (`is` / `validate`) and a `Schema`.
- **Structural rule** (`notWithin`) — a feature a profile allows, but not inside a given node (RTF's `Strong` in a `Header`, #197). The phantom `F` can't express it, so only `is` / `validate` and `narrow` enforce it; `narrow` handles the inner node as if the profile lacked the feature there.
- **Widen / narrow** — moving a document to a superset profile (free, by assignability) or a subset one (lossy, reported).
