# @thomasfosterau/effect-csv (packages/csv)

CSV and TSV for the core's `Csv` profile: dialects (`dialect.ts`), the effect-parse grammar and the chunked streaming scanner (`scanner.ts`), the whole-text scanner's fast path (`fast.ts`), the reader with type inference (`reader.ts`, and `readCsvRows` beside it), plain-decimal reading (`decimal.ts`), the writer (`writer.ts`), and seeded synthetic data (`synthesize.ts`).

## Boundary

Peers: `effect`; dependencies `@thomasfosterau/effect-document` and `@thomasfosterau/effect-parse` (import its subpaths `/Parser`, `/Token`, `/ParserStream`, `/SyntaxError`, …). `.fallowrc.json` zone `csv` may import `core` only.

## Invariants

- **A CSV document is one `Worksheet`**, its rows without gaps, of plain cells (bare numbers, booleans and text) and `CellText` / `CellNumber` / `CellBoolean` / `CellBlank`, with the header row as column names: `treatFirstRowAsHeader` decides, and unset the reader sniffs it (a text first row over a column of numbers or booleans; owner decision on #88). The scanners see raw strings only, so unset means no header there. The reader never emits another node.
- **Type inference is opt-out and lossless to turn off**: `inferTypes: false` keeps every value a text cell exactly as written. It types whole columns by default (`inference: "column"`, owner decision on #88); `"cell"` is the opt-in.
- **Whole-text and streaming scans agree.** `scanCsv` and `scanCsvStream` use the same row grammar; a field, a quoted line break or a CRLF split across stream chunks parses as if it were not. A whole-text failure carries its source position; a streaming one is positioned within the unconsumed buffer, so it carries none.
- **`scanCsv` has a hand-written fast path** (`fast.ts`) for one-character separators and wrappers escaped by doubling, without `trimWhitespace`, `lineCommentMarker`, `quoteAnywhere` or `skipRows`. It must return exactly the grammar's rows, and it hands any input the grammar rejects (an unclosed quote) back to the grammar, so errors stay the grammar's. The differential test in `test/csv.test.ts` ("CSV scanner fast path") compares the two on generated input across dialects; extend it with any option the fast path learns.
- **`read` has a one-pass fast path** (`fused.ts`) on top of the fast scanner, for options without `providedHeaders` or `validateHeaders` (and, for a sniffed header, with column inference): it types each row as the scanner reads it, by a guess at each column's type from its first non-null value. It gives up, and the general path (scan, then type by column, then build) runs from the start, whenever a value contradicts its column's guess, a row's width is off while widths are checked, or a quote is unclosed; so its documents and errors are the general path's. The "CSV reader fast path" test compares the two over generated tables and option sets. Its rows hold plain cells (#226): a number, boolean or text value is its bare value, a blank a `CellBlank`, so a value costs no node; a field of a column guessed to hold numbers is read from the text in place, without its string (both paths build the same forms, which the fast-path test compares). Plain decimals of up to 15 digits are read in the scan that classifies them (Clinger's fast path: exactly `Number(raw)`).
- **`readCsvRows` is `read` without the document**: the same header handling and the same typing, a value being its cell's `value` (`null` for a blank, the text for a text cell). It runs the same one-pass reader over the fast scanner (`fusedValues`), which types each field as it is read and reads a field of a number column straight from the text (`numberAt`), and otherwise the general path; the "readCsvRows" test compares it with `read` on both paths.
- **Plain decimals are read exactly as `Number` reads them** (`decimal.ts`), and a number must hold its digits (a decimal a double cannot hold stays text): up to 15 digits by Clinger's fast path, and a longer one by computing its double from the digits (a quotient corrected by an exact Dekker residual, kept only within half an ulp) and checking that it prints back as written; whatever that cannot settle within its rounding margin goes to `Number` and `String`. The classifier test ("classifies numbers as the plain-decimal grammar does") checks it against the regular-expression reference on printed doubles, nudged ones and random long digit strings.
- **The hot call sites stay monomorphic, and number rows stay doubles** (`fast.ts`, `decimal.ts`; measured on bench/csv.bench.ts). A number read in place goes through `decimalInText`, which only ever scans the source text (a scan that also meets sliced strings runs at half the speed); `readRecord` gives the string scan's slices to one call target; a row that follows an all-number row starts as a copy of a template of doubles and stores through `storeNumber`, a store site of its own, so V8 holds its numbers unboxed (a store shared with generic rows turns them generic). Keep these separations when editing the scanner.
- **The grammars are compiled (`Compiler.jit`) and memoized** per dialect-and-options key, least recently used dropped at 32 entries: the whole-text grammar (`tableParser`), the streaming row grammar (`rowParser`, keyed without `skipRows`, which the stream drops before parsing). `ParserStream.parseMany` runs the compiled row grammar compiled and re-runs a failing row interpreted, so streaming errors are the interpreter's.
- **Synthesis is reproducible per seed**: the same `SynthesisSpec` with the same `seed` yields the same table (a Lehmer generator, row-major); without a seed the generator is seeded from Effect's `Random`.
